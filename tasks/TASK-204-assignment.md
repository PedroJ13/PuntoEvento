# TASK-204: Product/Release - aprobar alcance refresh visual antes de Web Dev

## Equipo asignado

Product / Architect / Release.

## Contexto

`TASK-203` debe producir una guia visual minima para marca y panel empresa. Antes de crear tareas Web Dev, Product / Architect / Release debe aprobar alcance para evitar rediseño profundo no controlado.

## Tarea

Revisar `tasks/TASK-203-HANDOFF.md` y decidir que parte pasa a implementacion.

## Alcance

1. Aprobar, ajustar o rechazar:
   - logo;
   - tagline;
   - paleta;
   - tono visual premium;
   - layout sidebar del panel empresa;
   - menu activo/deshabilitado.
2. Confirmar que Web Dev solo implementara:
   - branding base aprobado;
   - panel privado de empresas.
3. Confirmar que quedan fuera:
   - rediseño profundo pagina publica;
   - rediseño profundo admin interno;
   - rediseño perfil publico;
   - nuevos modulos funcionales.
4. Si se aprueba, crear tareas pequeñas para:
   - Web Dev branding base/panel empresa;
   - QA validacion visual/regresion minima.
5. Actualizar docs si se formaliza decision de identidad visual.

## No tocar

- No implementar codigo.
- No mandar Web Dev antes de leer y aprobar `TASK-203-HANDOFF.md`.
- No ampliar alcance a todo el producto sin decision explicita.

## Verificacion

- Decision clara: aprobado / aprobado con ajustes / no aprobado.
- Tareas Web Dev creadas solo si hay aprobacion.
- QA queda planificado despues de implementacion.

## Handoff esperado

Crear `tasks/TASK-204-HANDOFF.md` con:

- Decision tomada.
- Alcance aprobado.
- Alcance excluido.
- Tareas creadas para siguientes equipos, si aplica.
- Docs actualizados.
